Pipeline Stage Technical Specification & Code Architecture

Step 1: Edge Sensing & UDP Broadcast (ESP32 + DHT11)

The ESP32 microcontroller samples ambient temperature and humidity from the DHT11 sensor every 2 seconds. It serializes this data into a JSON payload and transmits it over UDP to destination port 5005.

IP(src="192.168.1.50", dst="192.168.1.255") / UDP(sport=52144, dport=5005) / Raw('{"temp": 24.5, "humidity": 58.2}')

Why UDP? UDP has minimal overhead for battery/compute-constrained IoT microcontrollers, but provides no encryption or handshakes, making it critical to passively monitor with an external NIDS.

🔬 The Mathematical Anatomy of NET-GUARD Features

Machine learning models cannot process raw Ethernet bytes directly. NET-GUARD converts passive telemetry into a 5-dimensional feature vector $\mathbf{x} \in \mathbb{R}^5$ in real-time. Here is how each feature operates:

⏱️ 1. Inter-Arrival Time (IAT)
2000 ms
$$\text{IAT}_i = t_i - t_{i-1}$$
Measures the time elapsed between consecutive packet arrivals. Under normal conditions, the ESP32 transmits predictably every ~2,000 ms ($\sigma \approx 50\text{ ms}$). During a UDP volumetric DoS flood, the IAT plunges to $0.5 - 5\text{ ms}$.
Traffic StateTypical ValueSignificance
Normal ESP321800 - 2200 msStandard periodic beacon
DoS UDP Flood0.1 - 10 msBuffer exhaustion attack
📊 2. Shannon Byte Entropy
4.25 bits
$$H(X) = -\sum_{j=1}^{256} P(b_j) \log_2 P(b_j)$$
Measures the information randomness of the payload bytes. Structured ASCII JSON has an entropy between $3.8 - 4.6\text{ bits/byte}$. Random binary fuzzing or encrypted data exfiltration spikes entropy toward $7.5 - 8.0\text{ bits/byte}$, while repeated string floods plunge it toward $1.0\text{ bit/byte}$.
Traffic StateTypical ValueSignificance
JSON Telemetry3.8 - 4.6 bitsPredictable ASCII character set
Fuzzing / Exfil> 7.2 or < 2.0High randomness / Repetition
🌡️ 3. Physical Sensor Gradient
ΔT: 0.05°C/s
$$\nabla T = \frac{|T_i - T_{i-1}|}{\Delta t}, \quad \nabla H = \frac{|H_i - H_{i-1}|}{\Delta t}$$
Physical temperature cannot jump $50^\circ\text{C}$ in a 2-second interval due to thermal mass constraints. If $\nabla T > 5^\circ\text{C/s}$, this indicates physical sensor tampering, voltage glitching, or synthetic telemetry spoofing.
Traffic StateTypical ValueSignificance
Normal Ambient< 0.2 °C/sNatural thermal convection
Spoofed / Glitched> 15.0 °C/sImpossible physical change
🌲 4. Isolation Forest Score
0.18
$$s(x, n) = 2^{-\frac{\mathbb{E}(h(x))}{c(n)}}$$
$\mathbb{E}(h(x))$ is the average tree depth required to isolate sample $x$, and $c(n)$ is the average path length of an unsuccessful search in a BST. Anomalies are isolated in very few splits (small $h(x)$), causing $s(x, n) \to 1.0$.
Anomaly ScoreDecisionAction
$s < 0.50$Normal BaselineForward telemetry
$s \ge 0.70$High AnomalyTrigger SOC Alert

TP-Link TL-SG105E Port Mirroring Configuration Steps:

  1. Connect your laptop to the TP-Link switch and open the web management interface (default: 192.168.0.1).
  2. Navigate to Monitoring > Port Mirror.
  3. Set Mirrored Port (Source): Select Port 1 (ESP32) and enable Ingress & Egress.
  4. Set Mirroring Port (Destination): Select Port 5 (Connected to Laptop Ethernet).
  5. Click Apply. Your laptop Ethernet port will now silently receive 100% of the raw ESP32 packet traffic!
